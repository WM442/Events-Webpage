Events API Documentation

Complete reference guide for SOFT20181 Events API

Overview

The Events API is a RESTful API built with ASP.NET Core that manages events, organizers, comments, and messages. This API uses SQLite as its database and supports related data fetching.

Key Features

  • Event management with filtering capabilities
  • Organizer profiles with their associated events
  • Comment system for events
  • Message/contact system
  • Token-based authentication
  • Database management utilities

Getting Started

Base URL

http://localhost:5201/api

API Documentation UI

This page is the complete API guide. The starter app serves it at:

http://localhost:5201/api-documentation.html

Calling the API from Live Server or another app

The API allows browser calls from any origin, port, method, and request header through CORS. If your HTML is served by VS Code Live Server rather than this app, call the API with its absolute address (for example, http://localhost:5201/api/events), not a relative /api/events path. Protected endpoints still require a valid Bearer token.

CSS changes while developing

The starter HTML pages load local CSS through js/css-loader.js, which adds the current time as a version query and fetches the CSS without using the browser cache, including stylesheets pulled in by CSS @import. Add more local stylesheets to the loader's data-css list when needed.

Content Type

All requests and responses use JSON format:

Content-Type: application/json

Authentication

Most endpoints require authentication using a Bearer token.

How Authentication Works

  1. Create an Auth Token (see Auth Endpoints section)
  2. Include the Token in Requests:
Authorization: Bearer your-token-here

Which Endpoints Require Authentication?

Endpoint Authentication Required
/api/auth No
/api/messages No
/api/auth/{id} and /api/messages/{id} (PUT/PATCH/DELETE) Yes
/api/events Yes
/api/organizers Yes
/api/comments Yes
/api/config No

Data Models

Event

{
  "id": 1,
  "category": "Tech",
  "title": "Web Development Workshop",
  "description": "Learn modern web development techniques",
  "location": "London",
  "eventDate": "2025-12-15T14:00:00",
  "organizerId": 5,
  "imageUrls": "https://example.com/image1.jpg",
  "organizer": { /* Organizer object */ },
  "comments": [ /* Array of Comment objects */ ],
  "images": ["https://example.com/image1.jpg"]
}

id auto-generated - Unique event identifier

category required - Event category (e.g., "Tech", "Sport", "Music")

title required - Event title

description required - Event description

location required - Event location

eventDate optional - When the event occurs

organizerId optional - ID of the organizer

imageUrls optional - Comma-separated image URLs (e.g., "url1,url2,url3"). Returns as images array in response.

organizer - Related organizer data (not stored)

comments - Related comments (not stored)

images - Parsed array of image URLs from imageUrls (not stored)

Organizer

{
  "id": 1,
  "fullname": "John Smith",
  "email": "john@example.com",
  "imageUrl": "https://example.com/avatar.jpg",
  "events": [ /* Array of Event objects */ ]
}

id auto-generated - Unique organizer identifier

fullname required - Organizer's full name

email required - Valid email address

imageUrl optional - URL to organizer's profile image

events - Related events organized by this person (not stored)

Comment

{
  "id": 1,
  "eventId": 10,
  "author": "Jane Doe",
  "content": "Great event! Looking forward to it.",
  "event": { /* Event object */ }
}

id auto-generated - Unique comment identifier

eventId required - ID of the event being commented on

author required - Name of the comment author

content required - Comment text

event - Related event data (not stored)

Message

{
  "id": 1,
  "fullname": "Alice Johnson",
  "email": "alice@example.com",
  "phone": "+441234567890",
  "content": "I have a question about your events."
}

id auto-generated - Unique message identifier

fullname required - Sender's full name

email required - Valid email address

phone optional - Contact phone number

content required - Message content

AuthToken

{
  "id": 1,
  "fullname": "Developer User",
  "token": "123e4567-e89b-12d3-a456-426614174000"
}

id auto-generated - Unique token identifier

fullname required - User's full name

token auto-generated - Authentication token (GUID)

Auth Endpoints

POST /api/auth No Auth Required

Create Authentication Token

Use Case: Generate a new authentication token for API access. Create a token before accessing protected endpoints (Events, Organizers, Comments).

Request Body

{
  "fullname": "John Developer"
}

Response (200 OK)

{
  "id": 1,
  "fullname": "John Developer",
  "token": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}

Example (cURL)

curl -X POST http://localhost:5201/api/auth \
  -H "Content-Type: application/json" \
  -d '{"fullname": "John Developer"}'

Example (.http file)

POST http://localhost:5201/api/auth
Content-Type: application/json

{
  "fullname": "John Developer"
}

Example (JavaScript Fetch)

const response = await fetch('http://localhost:5201/api/auth', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    fullname: 'John Developer'
  })
});

const data = await response.json();
console.log('Your token:', data.token);
// Save this token for future requests!

Events Endpoints

GET /api/events Auth Required

Get All Events

Use Case: Display a list of events, search for specific events, or filter by category/location.

Important: This endpoint ALWAYS returns events with their related organizer and comments data automatically loaded.

Query Parameters (all optional)

title - Search in event titles (partial match, case-insensitive)

location - Search in locations (partial match, case-insensitive)

search - Search across title, description, and location (partial match)

Example (cURL)

curl http://localhost:5201/api/events \

Organizers Endpoints

GET /api/organizers Auth Required

Get All Organizers

Use Case: Display a list of event organizers, optionally with their events.

Query Parameters

withRelated optional - Add this as a URL query parameter to include related events

How to use withRelated:
Add ?withRelated=true to the URL to load related data.
Any non-empty value works: ?withRelated=true, ?withRelated=yes, ?withRelated=1

Without: GET /api/organizers → events will be null
With: GET /api/organizers?withRelated=true → events array will be populated

Example - Without Relationships (cURL)

curl http://localhost:5201/api/organizers \
  -H "Authorization: Bearer your-token-here"

Example - With Relationships (cURL)

curl "http://localhost:5201/api/organizers?withRelated=true" \
  -H "Authorization: Bearer your-token-here"

Example (.http file)

GET http://localhost:5201/api/organizers
Authorization: Bearer your-token-here

###

GET http://localhost:5201/api/organizers?withRelated=true
Authorization: Bearer your-token-here

Update and Delete Endpoints

Every resource supports PUT (replace the whole record using the same fields as its Create endpoint), PATCH (change only the fields you send; send null to clear an optional field), and DELETE (returns 204 No Content). The route id is authoritative. All update/delete actions require a valid Bearer token; there are no roles or ownership checks. Unknown ids return 404 and invalid data or links return 400.

EndpointMethodsNotes
/api/auth/{id}PUT, PATCH, DELETEToken must be non-empty and not used by another record.
/api/events/{id}PUT, PATCH, DELETEDeleting an event also deletes its comments. Link with organizerId or a nested organizer.
/api/organizers/{id}PUT, PATCH, DELETEDeleting an organizer keeps its events and unlinks them.
/api/comments/{id}PUT, PATCH, DELETEChange eventId (or nested event) to move a comment; the event must exist.
/api/messages/{id}PUT, PATCH, DELETEReading/creating messages stays public; modifying them requires a token.

Working with Relationships

What are Relationships?

In this API, some data is related to other data:

  • Events belong to Organizers
  • Events have many Comments
  • Organizers have many Events
  • Comments belong to Events

How to Load Related Data

Events Endpoints: Always includes relationships - no query parameter needed.
GET /api/events → Returns events with organizer and comments
Organizers & Comments Endpoints: Use withRelated query parameter to include related data.
GET /api/organizers?withRelated=true → Returns organizers with their events

Why Use withRelated?

Benefits:

  • Get all data in one request (fewer API calls)
  • Reduce network latency
  • Easier to work with related data

When to use:

  • ✅ When you need to display related data together
  • ✅ When building detailed views
  • ❌ When you only need basic information (saves bandwidth)

Examples

Without Relationships (2 requests needed)

# Step 1: Get organizer
curl http://localhost:5201/api/organizers/1 \
  -H "Authorization: Bearer token"

# Step 2: Get their events separately
curl "http://localhost:5201/api/events?organizerId=1" \
  -H "Authorization: Bearer token"

With Relationships (1 request)

# Get organizer with events in one request
curl "http://localhost:5201/api/organizers/1?withRelated=true" \
  -H "Authorization: Bearer token"

Error Handling

HTTP Status Codes

Code Meaning When It Happens
200 OK Request successful
401 Unauthorized Missing or invalid auth token
404 Not Found Requested resource doesn't exist
400 Bad Request Invalid request parameters
500 Internal Server Error Something went wrong on the server

Common Error Scenarios

1. Missing Authentication Token

curl http://localhost:5201/api/events
# Response: 401 Unauthorized

Solution: Include the Authorization header

2. Invalid Token

curl http://localhost:5201/api/events \
  -H "Authorization: Bearer invalid-token"
# Response: 401 Unauthorized

Solution: Create a new token using POST /api/auth

3. Resource Not Found

curl http://localhost:5201/api/events/99999 \
  -H "Authorization: Bearer your-token"
# Response: 404 Not Found

Solution: Check that the ID exists

4. Missing Required Fields

curl -X POST http://localhost:5201/api/events \
  -H "Authorization: Bearer your-token" \
  -H "Content-Type: application/json" \
  -d '{"title": "My Event"}'
# Response: 400 Bad Request (validation error)

Solution: Include all required fields (category, description, location)

5. CORS or Wrong-Port Error

The API is configured to accept browser calls from any origin, port, method, and request header, so pages served by VS Code Live Server (for example http://127.0.0.1:5500) can call an API running on http://localhost:5201.

If a browser call still fails, check:
1. The API app is running.
2. The fetch uses the API's absolute address, not a relative /api/... path (a relative path goes to Live Server).
3. The port in the fetch address matches the port printed when the API started.
4. Protected endpoints include Authorization: Bearer YOUR_TOKEN; CORS permission does not replace authentication.
5. An https:// page cannot call an http:// API because browsers block mixed content; use matching schemes during development.

Key Concepts

  • Authentication: Required for Events, Organizers, and Comments, plus every update/delete action (including AuthTokens and Messages). Any valid token works - there are no roles or ownership checks.
  • Relationships: Use withRelated param for Organizers and Comments; Events always include relationships
  • Filtering: Events support category, title, description, location, and search params
  • Error Handling: Check HTTP status codes and handle 401, 404, 400 appropriately
  • Development: Use Config endpoint to reset and populate database with test data
